## GPU initialization and deployment recovery

The first calibration smoke job produced no answers: FlashInfer required `nvcc`, absent from the Debian-only image. The driver and deployment were stopped to end repeated failed startups. Use NVIDIA CUDA 13.0.3 devel (the CUDA version pinned by vLLM 0.33.0's Dockerfile), with Ninja and a compiler. Keep H100 and sampling unchanged. Startup failures are delivered through the method instead of repeatedly raising from Modal's lifecycle hook; startup and execution have separate 600/1800-second limits. The prior GPU reservation remains retained until reconciled; failed runs are not evaluation results.

Modal rejected a subsequent deployment because source files changed during its build. `openwsp replicate` now deploys an immutable temporary source snapshot. This permits development during builds without changing the source that a launched run uses.

The first GPU smoke finished and its durable result was saved, but scoring failed because the released `mathqa.py` imports an unreleased `mcqa.loop_signals`. Its `extract`/`is_correct` grading functions never use that diagnostic. Keep the authors' file unmodified and provide a compatibility import that raises `NotImplementedError` if the missing diagnostic is called. Regression tests exercise the real extraction and math-verify grading. Resume from the saved GPU receipt, without generating the same answers again.
