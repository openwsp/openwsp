# Editor output recovery

The recorded Astra failures wrote complete fenced blocks followed by long backtick/blank-line loops. The [structural audit](../replications/exp8/results/live-run/editor-format-loop.json) retains counts and hashes; the [cost audit](../replications/exp8/results/live-run/editor-cost-analysis.json) derives charges from saved provider usage. None of the incomplete blocks was executed.

The adapter now creates background streams, watches output-text deltas and requests cancellation when a bounded suffix detector identifies that formatting loop. Routine cursor/tail persistence is batched; response IDs, cancellation intent, terminal events and errors are committed immediately. A disconnected stream reconnects to the same response with the last saved sequence number. It never repeats an ambiguous create.

The default ceiling returns to32,768 output tokens, including reasoning. Explicit verbosity is optional. The recorded responses used medium verbosity; current public Codex Astra configuration selects low. The authors' exact CLI version and request defaults were not released, so that difference is a hypothesis to test, not a demonstrated cause. No internal Codex routing headers are copied.

Cancellation does not establish final billing or safe continuation. A cancelled response without usage retains its full reservation. Known usage is settled once, including when cancellation races with completion. A formatting loop blocks additional requests and handoffs in that conversation. No cancelled or incomplete prefix is delivered as executable output.

`AstraEditor.acknowledge_runaway(response_id, reason=..., evidence=...)` records an explicit review of a matching, settled completed/incomplete response. It requires an evidence source, preserves the original receipt and response chain, and writes an immutable audit. Cancelled, failed, pending and unknown-usage outcomes cannot be acknowledged this way. Replaying the reviewed request key still raises; a later response loop blocks independently. This mechanism does not certify a protocol decision or automatically authorize further spending.

For the recorded Experiment 8 incident, `openwsp replicate exp8 --stage editor_probe` applies the [explicit user allocation](../replications/exp8/authorizations/editor-budget-20261103.json) once, then runs two synthetic formatting turns each with low and omitted verbosity. It admits at most $2 of editor reservations/charges across the probe, inside the attempt's allocation. It supplies no weights, practice examples or benchmark information and dispatches no generated code. Saved response IDs, usage, returned verbosity and format checks make the comparison reviewable. A short successful check does not establish long-run reliability. This paid probe has not run: the user now prefers subscription billing, and Codex CLI feasibility is being checked first.

After inspecting a successful probe, `--stage review_live` can review only the recorded turn 26/pass 4/runs 10 trajectory and its exact final response ID. It retains all history, weights and the existing API `previous_response_id` lineage, selects explicit low verbosity and the 32,768 ceiling for subsequent calls, and preserves the required forty-turn handoff. An editor turn that was never admitted receives the ordinary kernel-restart notice before its next action; an admitted request's input is never rewritten. Both this review stage and live resume remain on hold while Codex subscription feasibility is checked. A transfer of the API reasoning context into a Codex session is unverified; replaying visible messages does not establish continuity. If the API path is retained, the normal `openwsp replicate exp8` resumes only after this review succeeds and the coordinator confirms its previous owner terminal.

These stages are not invoked automatically by a fresh replication. The recorded budget allocation belongs to the existing spend baseline; it cannot silently enlarge a fork's initial budget. The protected PlanB allocation is not available to this attempt.
