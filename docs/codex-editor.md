# Codex CLI editor adapter

`openwsp.editors.codex.CodexEditor` implements the generic editor interface through a pinned Codex CLI and a caller-provisioned ChatGPT login. It does not select or migrate the editor used by Experiment 8. Subscription usage is recorded without applying API token prices or claiming a zero-dollar cost.

## Setup and use

Provide an installed `codex-cli 0.163.0` and a private, writable Codex home already provisioned through the CLI's normal ChatGPT authentication workflow. The adapter does not read, copy, export, or refresh credential values itself. The CLI uses its own authentication store. The adapter forces `forced_login_method="chatgpt"` and excludes API-key environment variables rather than falling back to an API account.

```python
from openwsp.editors.codex import CodexEditor

editor = CodexEditor(
    state_dir="/absolute/private/editor-state",
    codex_home="/absolute/private/provisioned-codex-home",
    executable="codex",
    max_wait_seconds=3600,
)
reply = editor.complete("Inspect the supplied weight statistics.", request_key="turn-001")
```

Both directories must be owned by the current user, have mode `0700`, and have no symlink components. The adapter creates a missing state directory, but the caller supplies the existing Codex home. It sets `CODEX_HOME` for the subprocess only. Proxy and CA-trust settings are preserved. Do not put these private directories or their journals in public result artifacts.

The constructor also accepts `work_dir`, `catalog_path`, `poll_interval`, `on_poll`, `output_validator`, and `commit`. `work_dir` defaults to `state_dir/work` and must also be private, owned by the current user, mode `0700`, and free of symlink components. Before each launch, the adapter checks the working directory and every ancestor for the presence of `.codex/config.toml` and refuses to launch if one exists. It does not read those config files. Supply an isolated private directory, such as one under `/tmp`, when the state directory is inside a configured project; the adapter does not silently move or migrate its working directory.

The CLI version and catalog digest are checked before a new launch. A custom catalog path must contain the exact pinned bytes, with SHA-256 `05723cac0f7da85c31f710f602bb0c47a5588d8bdf68aad24e9dd6ac951c7705`.

The verified configuration selects `gpt-6-astra`, reasoning effort `max`, verbosity `low`, and the one-line instruction `Answer the user's request.`. Native tools, web search, agents, skills, hooks, apps/plugins, and injected environment/project instructions are disabled. User configuration and user/project execution-policy rules are ignored; project configuration must be absent as checked above. The standard CLI still has system and managed configuration layers. The no-tools claim applies to the pinned configuration in the inspected deployment, not to every possible host configuration or an OS sandbox guarantee. The subprocess runs from a private working directory with read-only sandbox settings and no approval prompts. These are the settings exercised by the [local transport check](../scripts/check_codex_transport.py); the sandbox flag alone is not a no-tools guarantee.

The local check uses a mock HTTP endpoint to inspect the request generated by the actual CLI, including an exact-UUID resume. It verifies request construction, not real-provider authentication, model availability, semantic refusal behavior, or subscription entitlement. The standard built-in OpenAI provider has its own transport retries, and this CLI rejects provider retry overrides for that built-in provider. The adapter guarantees one CLI launch per durable request, not zero internal network retries. It preserves the standard ChatGPT route rather than substituting a custom provider to change retry behavior.

## Persistent turns and recovery

`complete(messages, request_key=...)` accepts one new, nonempty user message, either a string or a one-element role/content list. The CLI retains the earlier conversation. The adapter saves the UUID from `thread.started` and uses that exact UUID for later `exec resume` calls. A different returned thread ID is rejected. It does not use `--last`, resume by a mutable name, or silently start over when recovery fails.

Use a distinct stable key for each intended turn. A completed key with identical input returns its saved outcome without launching the CLI; a different input under the same key is refused. `new_conversation()` explicitly starts a fresh thread while retaining completed-request receipts, so keys must remain distinct across handoffs. It cannot reset an unresolved pending launch.

`has_request(request_key)` checks durable local records without creating state or launching the CLI. It returns true for a consistent pending or completed request, false when no record exists, and raises `UncertainRequest` for busy, orphaned, missing, or inconsistent records. A remote worker recovering an already-dispatched request must require true before calling `complete`; false is not permission to repeat that dispatch. A known pending request can still have an uncertain outcome.

Each request has a private directory containing its prompt, neutral instructions, command/configuration record, JSONL events, stderr, process/exit records, final message, and receipt. Launch intent is saved before starting the process. `commit` lets the caller make that state durable on its storage system. After intent is saved, a missing exit record, timeout, interrupted invocation, inconsistent output, or ambiguous terminal evidence raises `UncertainRequest`; the adapter never automatically repeats that launch. Inspect the private evidence and resolve the situation explicitly. There is no public method that invents completion evidence or guarantees recovery from a process that disappeared before saving its exit record.

`max_wait_seconds` bounds the subprocess wait; `poll_interval` is positive and at most 60 seconds. `on_poll` can maintain the caller's supervision while waiting. Incremental JSONL checks stop the running CLI on an error, model reroute, prohibited native-tool item, or mismatched thread ID. These interrupted launches and timeouts leave the request pending and raise `UncertainRequest`. A callback failure propagates its original exception and also leaves the launch pending; a later completion attempt raises `UncertainRequest`. None is automatically relaunched. Stopping the CLI does not prove that a remote generation stopped or used no subscription quota.

## Delivery and usage

Delivery requires a consistent thread ID, a `turn.completed` event, a successful process exit, valid usage fields, and agreement between the last completed `agent_message` and the CLI's final-message file. Partial text alone is never deliverable. Native tool items, reroute/warning/error items, unknown events, and failed turns prevent normal delivery. Failed or rejected outcomes retain their evidence and block further turns until an explicit handoff; ambiguous launches remain pending.

The CLI JSONL schema has no structured refusal field. Optional `output_validator(text)` can raise `EditorRefused` for caller-defined refusal handling, or `EditorError`/`ValueError` for invalid output. This is a caller decision, not a provider-authenticated refusal classification. A built-in structural guard checks completed text for runaway formatting; it is not a semantic safety classifier or an in-flight cancellation mechanism. Rejected text stays in the private raw artifacts and is not returned as accepted editor output. The generic adapter returns accepted text to its caller; it never executes model-generated code or commands itself.

`last_response` contains the receipt. Its `usage_snapshot` records the CLI's cumulative counters and, when justified, the difference from the preceding reliable snapshot of the same thread. The five counters are `input_tokens`, `cached_input_tokens`, `cache_write_input_tokens`, `output_tokens`, and `reasoning_output_tokens`. Preserve their meanings; do not sum cumulative snapshots or add reasoning counters to output totals again.

Codex 0.163.0's implementation emits thread-wide totals even though its event-type comments call them per-turn usage. An actual two-turn local mock confirmed totals of 10 input/2 output tokens followed by 20 input/4 output tokens. The source also emits all-zero counters when no usage notification is available. Accordingly, a zero snapshot, missing baseline, or counter regression cannot establish a precise per-turn delta. Failed turns may have no usage receipt at all. These limits do not imply free usage, and the adapter does not infer API dollars from subscription counters.
