PART 3. WORK THAT NEEDS NO GPU (do this while blocked; each item is a command or a stage with a CPU test in CI and a result file the reporter reads)
3.1 inspect (core API, exposed in CLI, SDK and MCP alongside diff and export_edit). Input: an edit directory in edit format v1 or the authors' legacy format. Output per tensor: changed rows and columns, rank of the delta by SVD, dominant direction(s), relative Frobenius change, and whether the delta is rank one of the form outer(u, u W0) with the implied coefficient per column. Across edits: cosine between dominant directions (p50c vs control2_mechanical is the first number to publish; p50c layer 15 vs layer 19 should give about 0.85). Logit lens: cosine of each direction with the unembedding rows of "Wait", "But", "Hmm", "So", "Okay" and with the mean unembedding row, using the tied embedding; if a direction is mostly a token direction, say so in the README. Pure numpy on CPU; test it on the tiny network with a planted rank one edit.
3.2 Eval grid as replication stages. One config file per cell producing summary.json in the results schema, plus one new summary field, accuracy_finished (correct among samples whose finish_reason is not the token limit) and finished_n, computed from the per sample records; the reporter adds that column next to accuracy and cut_share for every row. 3.3 repair, a replication stage generalizing control2 into an agent free baseline anyone can run on another model: inputs are two text sets (looping vs finished, or any contrastive pair), target layers, a column rule (all columns, or the published score rule: projection onto u times mean activation difference, top k), and a coefficient; it builds u by difference of means, applies W' = W minus alpha outer(u, mask (u W)), and exports edit format v1 with provenance. Define three variants now: 2a all columns coefficient 1 (textbook ablation), 2b all columns coefficient 6, 2c mechanically selected 64 columns coefficient 6; then a dose sweep alpha in {0, 1, 2, 3, 4, 6, 8} on 100 problems x 1 sample. Building the edits is CPU; scoring waits for GPU. Dual use rule unchanged: the repo ships only the repetition fix; no refusal related texts, edits or examples.
