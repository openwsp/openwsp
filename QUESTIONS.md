# Later questions and chosen defaults

No further user input is required. Record uncertainties and the chosen defaults here.

- Control 1: the pinned model card distinguishes its benchmark settings (0.7/0.8/1.5) from recommended non-thinking text settings (temperature1.0/top_p1.0/presence2.0/top_k20/min_p0/repetition1). Use the dedicated text recommendation, thinking disabled, keep32768 token cap for comparison. Source: https://huggingface.co/Qwen/Qwen3.5-0.8B/blob/2fc06364715b967f1860aea9cf38778875588b17/README.md . No result-dependent tuning.

- Control 2 needs a definition of looping and token aggregation. Default chosen before scores: length-cut answers with at least 50% duplicate 8-grams in the final 1,024-word tail, contrasted with all stop-finished answers; equal weight per answer, mean MLP output over its first 8,192 answer tokens. Normalize each layer's mean difference, remove alpha=6 times its projection from exactly the 64 columns changed by p50c. This uses calibration MATH-500 answers as requested and is labeled a diagnostic, not a held-out estimate.
- Controls run alongside the live run only when the verified budget can reserve headroom for the live run and required evaluation. Otherwise the user's spending priority takes precedence and controls wait. Missing controls are never reported as evaluated.
- When available Modal headroom falls below $20, paired passes may reuse previously recorded base generations for exactly matching problem/prompt, sampling, pinned model/engine and fixed seed. Its use is recorded per forward request and disclosed in the final report.
- Modal allowance visibility: the supported Starter SDK exposes usage totals but not the current workspace usage limit. The billing guide says successful charges can raise the maximum budget that can be set; that does not establish an increased current limit. Default: continue under $42 until an actual current-limit observation exists, even after a charge. Read-only review: `logs/modal-allowance-visibility-review.json`; dashboard: https://modal.com/settings/usage . No billing setting was changed.

- The authors did not publish an editor API output-token ceiling. Our initial 32768 ceiling caused a terminal `max_output_tokens` response at t011. Default: use Astra's documented 128,000 maximum for future responses; record the truncated response as a non-executed editor turn, charge its usage once and retain its `previous_response_id` lineage. Supply only the neutral API failure, with no scientific hint. Do not regenerate that sampled response or execute partial text. Evidence: `replications/exp8/results/live-run/editor-output-limit.json`.

- Optional control 4: use independent unit-normalized standard-normal vectors at layers 15 then 19, from NumPy PCG64/default_rng seed 0, converted to float32 before normalization. Preserve the released p50c changed-column mask and alpha=6. Fix this before evaluation; no direction search or selection.
- Optional control 5: use native Transformers 5.17 generation with bf16 weights and SDPA over text inputs, the pinned tokenizer/template and exact think35 sampling (including generated-token-only presence penalty). Use the first 50 problems in saved MATH-500 order, smoke on the first four, and compare with those same IDs from the existing vLLM calibration. Reused records retain original raw-text hashes and report zero incremental generation cost, with the original cost in calibration. Equal seeds across engines do not imply identical random draws. A matched engine that cannot work within the one-hour debugging breaker is dropped and disclosed.
